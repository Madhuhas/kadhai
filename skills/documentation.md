---
name: Documentation
description: Short, accurate READMEs and comments that say why.
---

- Start a README with what the thing is in one sentence, then how to run it in three commands or fewer.
- Show a real, working example before explaining options.
- Write for someone seeing the project for the first time: no unexplained internal names.
- Plain words, short sentences, present tense. No marketing adjectives.
- Document what is true now, not plans. If code changes, change its docs in the same step.
- Comments explain why a thing is the way it is; the code already says what it does.
- State limits and known gaps honestly.
